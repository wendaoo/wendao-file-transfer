项目入口 · 自行打包说明

当前能完成本地构建，但公开共享仍需处理第三方分发许可、对应源码、许可证通知、截图脱敏及品牌配置。目录标为“需要共享”不代表其中所有第三方内容已获公开分发授权。

本地生成内容

文件夹用途共享时注意
node_modules/下载的 JavaScript 依赖，数量最多；由安装命令生成。不上传 Git
dist/、app/dist/、dll/编译后的应用、安装包、界面资源和开发预打包依赖。不上传 Git
.build-tools/、.cache/项目内工具链、下载缓存、检查记录和临时输出。不上传 Git
.git/本地 Git 的对象、索引和配置，由 Git 管理。不作为普通项目目录上传

按你要做的事查找

修改界面：app/containers/ 和 app/components/。修改设备功能：app/services/、app/data/ 和 ffi/。下载后自行打包：从 BUILDING.zh-CN.md 和 scripts/shared/ 开始。检查公开共享风险：阅读公开发布检查.html。

容易误解的目录

build/ 同时包含打包输入和原生程序、依赖库，不能当作缓存整体清理。app/ 中的 *.prod.js、*.map、dist/ 属于编译输出，与源码混放。docs/ 是历史网站输出，包含域名等站点配置；它与 docs-sources/ 是网站输出与源码的关系。

helpers/ 与 utils/ 都是辅助逻辑，不能仅靠名字严格区分职责。scripts/local/、scripts/cicd/ 与 internals/ 分别偏向本地编译验证、历史持续集成发布和打包内部流程。

为什么保留现有文件夹名称

应用导入、构建命令和打包配置引用现有目录，直接改中文名会影响运行。本说明按用途帮助阅读，不改变实际源码路径。

本地工作区与共享仓库

仅 wendao-file-transfer/ 是仓库根目录。外层安装包、本地工具、原始备份、清理归档和公开发布检查报告属于工作区材料，不需要一起上传。法律和许可方面的必要来源、许可证及分发说明仍需在仓库或发行包中保留，参见 THIRD_PARTY.md。
