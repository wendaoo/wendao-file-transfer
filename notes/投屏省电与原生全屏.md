# 投屏省电与原生全屏

绿色按钮问题：原先使用 DOM requestFullscreen。Electron 18.3.15 实测进入后 document.fullscreenElement 有值，但 BrowserWindow.isFullScreen=false、isFullScreenable=false，绿色按钮因此显示缩放加号。现在使用画面覆盖层，并保持窗口可进入原生全屏，不再调用 DOM requestFullscreen。

两级全屏：点击预览区下方的“全屏”先在当前窗口内展开；再点击左上角绿色窗口按钮进入 macOS 原生全屏。通过绿色按钮退出原生全屏后，保留窗口内展开的预览。画面中的“退出全屏”按钮或 Esc 返回普通布局，如处于原生全屏则同时退出。窗口内展开和原生全屏均采用高清档位。

投屏策略：
- 小窗：H.264、最长边1200px、最高15fps、目标码率4Mbps。
- 全屏：原生分辨率、最高30fps、目标码率12Mbps。
- 切换档位重建投屏会话，会有短暂重连；布局尺寸保持不变。
- 最小化：主进程立即停止当前投屏；渲染进程释放解码器，预览开关意图保留。
- 恢复：仅原先已开启的预览重新建立连接，关闭状态不会自动打开。
- 快速连续切换沿用会话取消与生命周期清理，旧异步回调不得关闭新的预览。

验证：PLJ110 小窗实际544×1200、全屏1080×2368；退出后回到544×1200。原生全屏时 isFullScreen=true、isFullScreenable=true，DOM不再全屏。最小化 active=false、无投屏子进程，恢复后重新开启；关闭后最小化/恢复保持关闭。完整 build-local 通过。

这些参数旨在降低小窗持续投屏的编码、传输和解码负担，未进行电池耗电百分比实测。

全屏过渡更新：在画布分辨率重置及 macOS will-enter/leave-full-screen 到 enter/leave-full-screen 期间，使用独立画布保存并覆盖上一帧；等待新画面完成两次 requestAnimationFrame 后撤掉覆盖层。仍需重建编码器的画质切换可能短暂停留在上一帧。编译及 ESLint 已通过；本次 ADB 设备列表为空，30fps 及防闪烁效果待重新连接设备后真机复验。
