# OpenMTP 分阶段改进

## 第一阶段：恢复可运行基线

目标：在现有 Intel Mac 上从源码构建、启动并生成独立预览安装包。

- 使用 Node 16.20.2 / npm 8.16.0 / Yarn 1.22.22 复现现有构建链。
- 优先复用仓库自带 Kalam / libusb；本阶段不重编译传输内核。
- 修正 Webpack 5 配置、原生构建入口、本地打包配置。
- 本地预览使用独立应用标识和配置目录，关闭原项目更新和统计上报。
- 验证生产构建、启动、原生库加载、文件浏览、DMG 打包。
- 真机上传下载为单独验收项，未执行时不能视为通过。

Node 16 和 Electron 18 仅用于复现基线，不作为后续正式发布的长期版本。

## 第二阶段：体验与可靠性

按小步可验证的顺序推进：

1. 建立传输测试样本与结果记录：空文件、中文名、重名、大文件、大量小文件。
2. 优化列表渲染，使用大目录样本对比加载时间和交互响应。
3. 提取界面文案并加入中文，保留语言切换。
4. 完善进度、错误提示、失败文件列表与重试。
5. 在已有任务模型上设计传输历史与持久化。

## 第三阶段：底层与发布

- 升级 Electron 和相关原生模块，逐步隔离渲染层系统权限。
- 评估 Go 依赖与 Kalam 重编译，建立 Intel / Apple Silicon 验证矩阵。
- 使用真机测量瓶颈后再优化吞吐量。
- 暂停、断点续传需先确认设备与协议支持，不通过界面状态模拟。
- 正式发布前配置独立更新渠道、签名、公证及第三方许可清单。

## 真机验收边界

只在新建测试目录内上传或下载生成的测试文件，不覆盖或删除用户已有文件。
验证文件数量、大小和可行时的哈希；断连、取消与空间不足测试须记录结果。
