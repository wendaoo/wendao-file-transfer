# 从设备列表拖出到 Finder

2026-09-22

## 原因

原来的 dragstart 只更新应用内部拖拽状态并设置拖拽图片，没有向 macOS 提供文件 URL 或文件承诺。手机路径不是 Mac 上的本地文件，Finder 无法接收。

## 实现

- macOS 列表与网格 dragstart 读取拖动项和当前多选集合，阻止默认 HTML 拖拽，交给原生 AppKit 拖拽会话。
- NSFilePromiseProvider 声明文件名/文件夹类型，Finder 确认接收后才启动下载，不在选中时预下载，也不要求准备后再拖第二次。
- 原生库通过 Koffi 与 Electron 主进程通信；窗口句柄按 NSView 指针解码。拖拽只允许复制，保留手机原文件。
- 交付任务串行复用原 ADB/MTP 下载与进度弹窗。连接身份变化或已有传输时拒绝该次交付。
- 下载到目标目录中的独立隐藏临时目录，完成后交付；文件以排他方式创建，已有目标不被静默覆盖。失败清理临时目录，并通过原生完成回调及应用提示报告。
- 打包包含 universal x86_64/arm64 dylib；`yarn build-local` 先编译该模块。

## 验证与边界

- 本机 macOS / Android 测试设备，1,440,000 字节随机文件经原生文件承诺委托、renderer 下载和目标交付完整链路，SHA-256 一致。
- 两个文件加一个含子文件、空目录的文件夹，串行交付成功；手机原文件仍存在，临时目录已清理。
- 目标已有同名文件时返回失败，原有内容保持不变。
- `node scripts/local/verify-device-drag.cjs` 可在带 9226 调试端口的开发预览中重复验证，需要已连接并授权的 ADB 手机。测试使用独立手机目录并在 finally 中清理。
- 集成测试调用同一 AppKit 文件承诺委托与 completion block，不模拟 Finder 鼠标输入；实际 Finder 拖放手势尚需用户验收。初次尝试直接以 NSPasteboard 构造 NSFilePromiseReceiver 的测试不适用（缺少拖拽会话填充的元数据），已移除该测试实现。
- 本轮 MTP 回退通道未进行真机拖出验证，下载仍复用原传输实现。
- 最终 lint、原生双架构编译、Electron 主/渲染进程构建通过。仅保留原工具链依赖警告。

## 双向拖拽复查（2026-09-22）

- 修复 Finder 拖入依赖历史 Redux 拖拽状态的问题：外部文件明确以电脑为来源，使用 drop 事件的目标区域；无需先触发 dragover 即可正确处理。
- 移除 200ms 延迟及读取全局复制队列的竞争条件。落下时直接保存此次文件列表、目标路径、存储编号和设备序列号，同名确认沿用该快照，取消立即释放。
- 明确 `dropEffect=copy`，去重拖入路径，传输中避免重复开始；确认前检查设备身份和存储是否发生变化。
- 更新回归脚本：调用界面的实际 drop 处理函数上传两个文件和一个文件夹，再通过 AppKit 文件承诺委托下载，校验内容、中文空格文件名、零字节文件和空目录；验证上传同名确认取消后源内容未被替换、下载目标同名时原文件未改变、暂存目录已清理。
- 真机 ADB 上述回归全部通过，协议/传输路由测试通过，完整 `yarn build-local` 通过。重启开发预览后执行，避免热更新遗留监听器干扰。
- 范围是共享存储中有读写权限的普通文件和目录；符号链接仍会明确拒绝。此次未真机验证 Kalam/Legacy，也未自动操作 Finder 的实际鼠标拖放手势。
