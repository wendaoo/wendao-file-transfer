# HarmonyOS 设备通过 HDC 投屏与文件互传的可行性

验证日期：2026-09-23。实机为 HarmonyOS 6.1 手机，HDC 3.2.0d，系统 API 24。

## 屏幕预览

- 当前 OpenMTP 已通过 `snapshot_display` 截图、`hdc file recv` 取回 JPEG，支持预览和全屏。实测约每秒一帧。此前仅指定截图宽度时，设备保持原始高度，导致画面拉伸；现在使用原生 1080×2504 截图，预览画布按同一宽高比显示。
- 当前设备 shell 中没有 `screenrecord` 命令。HDC 本身提供设备调试、文件传输和端口转发；没有实测到可直接输出连续视频流的投屏命令。
- 若要求 Android 式流畅投屏，需要设备端应用调用 AVScreenCapture 取码流，在用户确认录屏权限后编码视频，再经 HDC 端口转发传到 Mac。仅靠轮询截图难以获得同等体验。

## 文件互传

- OpenHarmony 官方 HDC 文档说明：API 21 起可对 `/mnt/data/<uid>/media_fuse/Photo/` 及其子目录执行部分媒体文件操作，`hdc file send` 可导入，`hdc file recv` 可导出；创建媒体目录不受支持。`-b` 可以访问符合条件的调试签名应用沙箱，不等于访问任意已安装应用。
- 本机设备的 HDC shell 能列出 `/mnt/data/100/media_fuse/Photo` 下的相册及媒体文件。将新建的 1×1 PNG 发入现有相册，再取回 Mac，字节比较一致；设备和 Mac 上的测试文件均已删除。应用内 HDC 通道已接入，文件区实测显示 12 个相册，测试文件经应用导入、导出、删除均成功且内容一致。
- 普通用户文件根目录 `/storage/media/100/local/files` 对当前 shell 身份不可列出。因此 HDC 媒体通道不能直接代替 MTP 提供完整的共享存储文件浏览；普通文档仍需 MTP，或另建经用户授权的设备端文件选择/传输应用。

## 实现建议

1. 保留现有 HDC 截图预览；流畅投屏作为需要设备端应用的独立阶段。
2. 已对媒体目录可访问的设备新增“照片与视频”HDC 入口，使用 `file send/recv` 做单个媒体文件的双向传输，并限制上传到已存在的相册目录；后续可优化缩略图与批量传输体验。
3. 普通文件继续尝试 MTP；连接失败时准确提示“媒体传输可用，普通文件目录不可用”，避免把媒体入口描述为完整存储空间。

## Android 式体验的验收边界

- 目标预览应是连续的视频码流，而不是周期性截图。设备端应用需在用户确认录屏后使用 AVScreenCapture 采集、编码 H.264，再经 HDC 端口转发传输；Mac 端解码并显示，同时验证帧率、延迟、旋转和停止时资源清理。当前约 1 帧/秒的截图链路不能满足“流畅预览”。
- 目标文件页应浏览设备通过 MTP 暴露的完整**用户共享存储**目录树，并支持双向传输。即使达到这一目标，也不意味着能读取其他应用的私有沙箱或系统文件。HDC shell 对当前设备的普通用户文件根目录无权限，单靠现有 HDC 命令无法补齐该目录树；设备端应用只能访问用户授权的文件或文件夹。
- 2026-09-23 再次只读诊断：现有 Kalam MTP 内核初始化 15 秒未返回，隔离子进程随后发生 SIGSEGV；旧版 `mtp-cli` 有一次枚举到“内部存储”，下一次打开又报告 USB 接口无法打开。暂停 HDC 服务期间也未稳定复现根目录列表，随后已恢复 HDC 连接。因此现在不能把媒体入口冒充完整文件页，也不能将未经验证的 MTP 路由直接设为默认。
- 后续首先在重新插拔、关闭可能占用 USB 的其他桌面设备管理程序后，以只读方式验证 MTP 根目录和连续会话；确认稳定后将 HDC 用于预览、MTP 用于共享文件树。若该设备 MTP 仍不稳定，需实现设备端应用，通过系统文件选择/授权获得可访问目录并与 Mac 双向传输。
- 重新插拔后的 USB 描述符确实同时列出 HDC Interface 与 MTP（接口类 6、子类 1、3 个端点），但 MTP CLI 连续两次根目录探测均在打开 USB 接口时失败；`-R` 重置选项和短暂重启 macOS Image Capture 服务也未解决。不能把“接口已暴露”误认为“文件树已可用”。
- 本机 Downloads 中有 HarmonyOS 6.1.1 公共 SDK（API 24），可以交叉编译设备端原生程序；但手机的 HDC shell 拒绝执行 `/data/local/tmp` 中用户编译的程序，连不访问屏幕的最小程序也返回 `Permission denied`。测试文件已清理。流畅预览需要真正的 HAP 安装、签名与屏幕录制授权，不能靠推送 HDC shell 可执行文件规避设备安全策略。
- HDC shell 对 `/storage/media/100/local/files` 仅有目录穿越权而无列目录权限；`/mnt/data/100/HO_MEDIA` 和文档映射也返回权限不足。没有发现能合法直接列出完整共享文件树的 HDC 路径。
- 清理旧版应用和占用进程后，旧版 `mtp-cli` 曾连续两次列出 MTP 共享存储根目录，证明设备并非完全不支持 MTP。相同状态下 Kalam 内核初始化超时并使隔离进程崩溃；再次启动旧版应用后，MTP 接口返回独占访问错误 `0xe00002c5`，此时 `-R` 和短暂关闭 `icdd` 均未恢复。
- 测试版现已在 HDC 设备接入时先用旧版 MTP 工具验证存储和根目录，验证成功则将设备文件页切到 MTP 完整共享目录并保留 HDC 预览；验证失败则回退到 HDC 相册页。MTP 命令设有 15 秒超时，传输失败不会再误报完成。仍需在手机 USB 模式重新初始化后，用测试版验证目录递进浏览及双向传输。
- 2026-09-23 相册刷新与缩略图修复：HDC 相册原来对每个文件分别调用 `stat` 和 `base64`，实机最大相册的 772 项在 45 秒内未完成。现在一次列出路径并分批 `stat`，同一相册约 1.6 秒返回全部 772 项。宫格视图对可见的照片按需用 HDC 取回并在 Mac 上生成小图，最多两个并发任务并缓存结果；实机普通相册当前可见 11 项已渲染出 11 个图片缩略图。
- ShareMedia 等相册可列出图片，但部分文件被 Media FUSE 报为 0 字节并拒绝直接读取。缩略图现可从设备媒体库查询同名记录、复制到 HDC 临时目录后取回生成，读取完清理两端临时文件；同名记录优先选择较新的媒体 ID。原图上限为 100 MB。实机 ShareMedia 的 57 项均能列出，顶部观察到 42 张缩略图，滚动到底部后实际可见区域的 36/36 张图片完成缩略图；PNG 也通过独立验证。目录刷新时内容区显示居中的读取进度，逐项缩略图另有转圈状态。
